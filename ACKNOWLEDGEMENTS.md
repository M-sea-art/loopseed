# Acknowledgements / 致谢

LOOPSEED One‑Shotted mode was shaped by studying the engineering pattern demonstrated in [mshumer/Claude-of-Duty](https://github.com/mshumer/Claude-of-Duty).

Special thanks to **Matt Shumer** and the contributors behind that public demonstration. Its most important lesson was not a single prompt or a specific game implementation, but the combination of:

- one human authorization that starts a longer autonomous run;
- an explicit architecture and ownership contract;
- repeatable, evidence-producing verification tools;
- independent critics rather than builder self-approval;
- repair or rollback after failed gates;
- honest, fail-closed completion criteria.

LOOPSEED generalizes those ideas into a project-agnostic, economy-oriented completion protocol for Codex. It is an independent implementation: no Claude-of-Duty game code or assets are included, and this project is not affiliated with or endorsed by Matt Shumer, Anthropic, or the Claude-of-Duty project.

We also thank the wider open-source agent, software-testing, and autonomous-coding communities whose work continues to improve reliable long-running AI workflows.

LOOPSEED 的 One‑Shotted 模式，受到公开项目 [mshumer/Claude-of-Duty](https://github.com/mshumer/Claude-of-Duty) 所展示工程方法的直接启发。

特别感谢 **Matt Shumer** 以及参与该公开演示的贡献者。我们学习的重点并不是某一句提示词或某个 FPS 的具体实现，而是以下完整机制：

- 一次人类授权，启动持续的自主执行；
- 明确的架构合同与所有权边界；
- 可重复、能产出直接证据的验收工具；
- 由独立评审者验收，而不是实现者自我批准；
- Gate 失败后的修复或回滚；
- 诚实、严格、默认拒绝虚假完成的终局标准。

LOOPSEED 将这些思想泛化为面向不同项目、强调经济性与减少重复提示的 Codex 完成协议。它是一个独立实现：仓库中不包含 Claude-of-Duty 的游戏代码或资产，也不代表 Matt Shumer、Anthropic 或 Claude-of-Duty 项目的官方关联或背书。

同时感谢更广泛的开源智能体、软件测试与自主编程社区，为可靠的长任务 AI 工作流提供了持续积累。
