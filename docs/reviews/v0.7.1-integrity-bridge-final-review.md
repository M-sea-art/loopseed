## Review question

Does v0.7.1 restore trustworthy candidate/artifact verification without expanding LOOPSEED into a heavier orchestration framework or claiming more integrity than it can prove?

## Findings

### PASS — candidate and artifact identity

The bridge binds the active verification generation to a real Git HEAD and stable deliverable artifact SHA-256. Tracked candidate drift, unexpected non-ignored untracked content, artifact mutation, artifact disappearance, and HEAD changes are fail-closed conditions.

### PASS — command execution is evidence, prose is not

Machine gates use `run-evidence` to execute the verifier command and record exit code, timeout, bounded stdout/stderr, candidate identity, and artifact state before/after execution. `record --command` is rejected because writing a command into a receipt is not execution evidence.

### PASS — stale evidence cannot silently survive repair

A repaired candidate receives a new verification-binding generation. Old gate PASS receipts are invalidated for the new subject. Finalization cross-checks the current run, task graph, gates, evidence, binding, blocking defects, and final report.

### PASS — required work must actually finish

Required tasks must be `SUCCEEDED`. Optional candidate arms must receive an explicit terminal disposition instead of remaining implicitly unfinished.

## Declared integrity boundary

v0.7.1 is a **Candidate & Artifact Integrity Bridge**, not a hermetic build or full supply-chain attestation system.

It does not automatically freeze or attest every possible verifier dependency. Mutable ignored source, environment state, external paths, model files, tools, services, or other inputs not represented by the bound candidate/artifact remain outside the current attestation boundary.

Therefore:

- verifier logic that determines PASS should be committed or otherwise frozen;
- projects should not silently depend on mutable ignored/external inputs for a v0.7.1 PASS;
- broader verifier-input provenance is a possible later experiment, not a blocker for this narrow release.

## Complexity review

The change is large in line count but remains concentrated on evidence execution, integrity checks, migration, finalization, locking, schemas, tests, and documentation. It does **not** add a new creative phase, new default expert topology, cross-project memory, gameplay mechanism, or new autonomous role.

The release therefore stays aligned with LOOPSEED's operating principle:

> No new mechanism without demonstrated product effect.
